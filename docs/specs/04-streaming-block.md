# 流式区块播放行为（细化项 #4）

> 状态：**已实现（M4b）**。构建侧 `src/lib/stream.ts`（hast → token 序列），前端 `src/scripts/stream-player.ts`，
> 节奏纯逻辑在 `src/lib/interactive.ts`（TDD 覆盖）。配置字段见 01-config-schema.md。

## 1. 渲染方式

**方案：增量渲染 markdown（推荐）**

- 播放前：内容 markdown 已在构建时渲染成"token 序列"（按字符/词切分但保持结构：标题、段落、列表项、代码块等作为单元边界）。
- 播放时：逐 token 追加到 DOM，markdown 结构随播随成型（标题立刻是标题、代码块带高亮逐行出现），而不是先出纯文本再整体"刷"成排版。
- 代码块：按行流出并即时高亮；链接、图片到完整节点时才出现，避免半截语法闪烁。

备选（否决）：逐字输出纯文本、结束后一次性渲染——实现最简单但视觉上有"先乱后排版"的跳变，不像真 LLM。

## 2. 播放控制

- `autoplay: true`：IntersectionObserver 检测进入可视区（50% 可见）自动播放一次；离开再回来不自动重播。
- 区块右上角常驻 **重播** 按钮（环形箭头图标），点击重新播放。
- 播放中显示闪烁光标（█ 或 ▍，主题色），播完光标淡出。
- `speed`：基础间隔（ms/token），配合随机抖动（±40%）模拟真实 LLM 节奏；标点后自动加短停顿。

## 3. 降级

- 用户系统开启"减少动态效果"（prefers-reduced-motion）时：不做流式，直接完整呈现。
- 无 JS 时：完整内容直接渲染在 `<noscript>` 内。

## 4. 性能

- ~~token 序列构建时生成 JSON，随区块懒加载（进入可视区附近才 fetch）。~~
  **实现决策（M4b）：token JSON 直接内联在页面里**（`<script type="application/json" class="stream-tokens">`）。
  单区块 ≤2000 字的 token JSON gzip 后仅几 KB，内联省一次请求往返、无加载瀑布，
  也免去"接近可视区再 fetch"的额外监听复杂度；体积超限时应先精简内容而非改懒加载。
- 单区块内容建议 ≤ 2000 字，播完总时长 ≤ 30s。
- `autoplay: false` 的区块直接完整呈现（不做流式），重播按钮仍可触发一次动画播放（M4b 决策）。
- 播放过程沿用逐 token 的容器高度过渡；不预先固定完整内容高度。完整内容离屏测量会把 `<noscript>` 内外两层内容容器重复计入，导致初始空白过高，因此该方案已实测并回滚。
